# 猫町OSIROイベント設定チェック 外部設計書

版: 業務チェック中心再構成版
更新日: 2026-08-25

本書は、オシロ管理者・業務担当者から見た業務仕様の正本である。最初に「何をチェックするか」を確認場所別に示し、その後に適用条件、イベントとチケットの見分け方、結果の扱い、料金表を記載する。

画面項目の詳しい読み取り方法、表記の統一方法、処理構成は`docs/内部設計書.md`を参照する。料金・販売対象の実装値は`src/domain/catalog.ts`を正本とし、第11章の料金表および回帰テストと同時に更新する。未回答の業務判断は0件である。

各チェック表では、「チェックする場合／チェックする券」にイベント・券の選択条件と除外条件を記載し、「正しい状態」には選択後の値・件数・一致条件だけを記載する。

## 1. このアプリが確認する内容

### 1.1 目的

OSIRO管理画面の募集中イベントを読み取り、設定不備または確認できなかった理由をコンソールとSlackへ表示する。

- OSIROは参照だけを行い、イベントやチケットを作成・更新・削除しない。
- 設定不備を自動修正しない。
- アーカイブ視聴機能そのものは確認しない。アーカイブ付きの参加券は通常の参加券と同じチェックを行う。
- 取得不能や分類不能を正常値へ置き換えない。

### 1.2 チェック全容

| 確認場所 | 主なチェック内容 | 詳細 |
| --- | --- | --- |
| イベント設定 | 申込締切日 | 第2章 |
| イベント本文 | 参加費、「今月1回目」「今月2回目以降」の表記 | 第3章 |
| 各チケット | 券名、金額、販売対象、「オンライン開催する」、URL、お知らせ | 第4章 |
| チケット構成・チケット間 | 必要券、参加形態、重複、プラン変更券、全回券、途中参加券、URL・お知らせの一致 | 第5章 |
| 本文とチケットなど異なる場所 | 受付開始時刻、書名 | 第6章 |

検出できない設定ミスは第7章に記載する。どのイベント・券へ各チェックを適用するかは第8章、イベントとチケットをどう見分けるかは第9章を参照する。

### 1.3 対象と実行方法

| 項目 | 内容 |
| --- | --- |
| オシロ管理者 | OSIRO管理画面とSlack通知先へアクセスできる担当者 |
| 一覧入力 | `state=yet_end`の募集中イベント一覧。次ページを最後まで取得し、同じ詳細URLを重複させない |
| 詳細入力 | イベント編集ページのタイトル、日時、会場、本文、締切、全チケット項目 |
| 認証 | `storageState.json`。ログイン切れは正常データとして扱わず実行失敗 |
| 手動実行 | `npm run check`。`SLACK_DRY_RUN=true`ではSlack本文を生成するが送信しない |
| 一覧確認 | `npm run list` |
| 認証更新 | `npm run auth` |

## 2. イベント設定のチェック

| ID | チェック項目 | チェックする場合 | 正しい状態 | 不備時に表示する内容 |
| --- | --- | --- | --- | --- |
| EVT-001 | 申込締切日 | 申込締切の設定がON | 締切日が開催日の3日前から開催日まで | 正しい日付範囲を示し、空欄・日付形式・日付を修正するよう表示 |

## 3. イベント本文のチェック

| ID | チェック項目 | チェックする場合 | 正しい状態 | 不備時に表示する内容 |
| --- | --- | --- | --- | --- |
| BODY-001 | 1回目の表記 | 本文の参加費欄に「1回目」の記載がある | 該当箇所がすべて「今月1回目」を含む | 該当する本文表記を修正 |
| BODY-002 | 2回目の表記 | 本文の参加費欄に「2回目」の記載がある | 該当箇所がすべて「今月2回目以降」を含む | 該当する本文表記を修正 |
| BODY-003 | オンライン参加費 | 本文に参加費欄がある、オンライン・通常料金・通常料金表のイベント | 第11章のオンライン本文参加費がすべて記載され、金額が一致 | 不足する対象者・回数・金額を本文で修正 |
| BODY-004 | オフライン／ハイブリッド参加費 | 本文に参加費欄がある、オフラインまたはハイブリッド・通常料金・通常料金表のイベント | 第11章のオフライン本文参加費がすべて記載され、金額が一致 | 不足する対象者・回数・金額を本文で修正 |

### 3.1 本文参加費の扱い

- 見出しは「参加費」「読書会参加費」の両方を許可する。
- 同じ金額の対象者を1行にまとめて記載してよい。確認時は対象者・回数条件ごとの料金区分へ分けて照合する。
- 対象者や条件を省略した行は、直前の記載から対象者を1通りに決められる場合だけ認める。
- 本文が空欄、または参加費欄がない場合はBODY-003/004をチェック不要とする。
- 参加費欄がある場合は、必須行の不足、金額不一致、金額形式不正を不備とする。
- 本文欄または本文構造を取得できない場合は確認不能とする。
- 1回目・2回目の記載がどちらもない場合、BODY-001/002だけをチェック不要とする。
- ゲスト料金、固定料金、通常参加券が0件のイベントにはBODY-003/004を適用しない。

## 6. 本文とチケットなど異なる場所の一致チェック

| ID | チェック項目 | チェックする場合 | 正しい状態 | 不備時に表示する内容 |
| --- | --- | --- | --- | --- |
| AREA-001 | 受付開始時刻 | オンラインまたはハイブリッドで、本文から受付開始時刻を1つ読み取れ、第5.6節でお知らせを確認する券が1件以上ある | チェック対象券すべてのお知らせに受付開始時刻があり、本文の時刻と一致する | 何番目の券のお知らせまたは本文を修正するか表示 |
| AREA-002 | 書名 | イベント名から書名を1つ読み取れ、全券が申込み済みではない。プラン変更券・運営メンバー券を券名の比較から除外する | 比較対象の券名にイベント名と異なる書名がない | 異なる括弧付き書名をイベント名の書名へ合わせる |

AREA-001は代表1券だけでなく、第5.6節でお知らせを確認する全券と比較する。お知らせ欄を取得できたが受付開始時刻がない場合は不備、欄自体を取得できない場合は確認不能とする。本文に受付開始時刻がなければチェック不要とする。

AREA-002では、券名から書名を読み取れない場合は「別書名なし」として正常とする。イベント名から書名を読み取れない場合はチェック不要、複数の書名候補から1つに決められない場合は確認不能とする。

## 7. 検出できない設定ミス

本アプリはOSIROに入力された値からイベントとチケットを見分けるため、作成者が本来意図した内容を完全には復元できない。次の設定ミスは、入力内容だけでは検出できない。

| 入力状態 | アプリの判定 | 検出できない本来の意図 |
| --- | --- | --- |
| 通常料金イベントの料金比較券をすべて誤って同額にした | 固定料金 | 本来は通常料金イベントだったこと |
| 本来は通常料金イベントだが料金比較券が1件だけ | 固定料金 | 作成者が通常料金を意図したこと |
| 固定料金イベントの複数券で1件だけ異なる金額にした | 通常料金 | 本来は固定料金で、異なる1件が金額誤りだったこと |
| 固定料金ハイブリッドで参加経路が欠落し、料金比較券が1件になった | 固定料金を維持し参加経路不足を検出 | 残った1件が本来どちらの参加経路だったか |
| ゲストイベントで1件でもゲスト料金を誤った | 通常料金 | 本来はゲストイベントだったこと |
| 通常イベントの全券をゲスト料金表へ一致させた | ゲスト料金 | 本来は通常イベントだったこと |
| 券名・金額・販売対象を別の有効な料金区分へそろえて誤設定した | 別の料金区分の正常券 | 本来意図した会員種別・回数区分 |
| 全回・途中参加・申込み済み・プラン変更の識別文言を別の有効な券名へ変更した | 券名から判定した別用途 | 本来の特別券用途 |
| イベント名と券名から全N回の文言を削除した | 全N回ではないイベント | 本来のセット参加イベントだったこと |
| 初心者・ビギナー文言をイベント名・全券名から削除した | 初心者・ビギナーではない | 本来必要だった運営メンバー券 |
| イベント名・会場を別の有効な開催方法表記へ変更した | 表示上の開催方法 | 作成者が本来意図した開催方法 |

これらは未回答事項ではなく、回答済みの分類方法を採用したことによる制約である。Slackには、入力された設定に対する判定であり、作成者の意図を推測した結果ではないことが分かる根拠を残す。

### 8.4 プラン変更券を必須にする条件

すべてのチェック対象イベントで、プラン変更券をちょうど1件必須とする。料金方式、通常参加券の件数、全N回、全回券、途中参加券、申込み済み券の構成による例外は設けない。

プラン変更券が必須ではないのは、イベント全体が対象外の場合だけである。チケット集合または券名を取得できずプラン変更券の件数を確定できない場合は、チェック不要ではなく確認不能とする。

## 9. イベントとチケットの見分け方

### 9.1 チェック対象・対象外

- 詳細タイトルに「予告」「一覧」「事務局決済」のいずれかを含むイベントは対象外とし、対象外理由を記録して後続の業務チェックを行わない。
- タイトルを取得できない場合は対象外と推測せず、対象判定不能とする。
- 対象外を除く募集中イベントをチェック対象とする。
- 一覧総数は「チェック対象＋対象外＋対象判定不能」と一致させる。

### 9.2 イベント自体の属性

| 属性 | 取り得る値 | 判定内容 |
| --- | --- | --- |
| 開催方法 | オンライン／オフライン／ハイブリッド | 会場とイベント名から判定 |
| 料金方式 | 通常料金／固定料金 | 料金比較券が1件以上あり、全券同額なら固定料金。それ以外は通常料金 |
| 料金体系 | 通常／ゲスト／料金表の確認対象外 | 通常料金表とゲスト料金表のどちらを使うか |
| 初心者・ビギナー | 該当／非該当 | イベント名または券名に「初心者読書会」「初心者限定」「ビギナー限定」があるか |
| 全N回イベント | 該当／非該当 | イベント名に全N回の表記があるか |

#### 開催方法

1. 会場が「オフ会場＋オンライン」ならハイブリッド。
2. それ以外でイベント名に「【東京】」「【大阪】」「【京都】」「【福岡】」「【名古屋】」「【愛知】」「東京開催」「文学フリマ」「猫町.で、旅をしよう」のいずれかを含めばオフライン。
3. 上記以外はオンライン。必要な会場・イベント名を取得できない場合は確認不能。

「【福岡 第N回】」だけを理由にオフラインとは判定しない。

#### 料金方式と料金体系

- 料金比較券群は、プラン変更券、運営メンバー券、申込み済み券、全回券、途中参加券を除いた券である。
- 料金比較券群が1件以上で全券同額なら固定料金。0件、または複数券で金額が異なれば通常料金とする。
- 金額を取得できず分類が変わる可能性がある場合は確認不能とし、通常料金と推測しない。
- 通常料金の場合、通常参加券群の全券が各料金区分のゲスト料金に一致すればゲスト料金とする。一部一致は通常料金とし、該当券を料金不備にする。
- 固定料金、または料金比較券群が0件の場合は料金表の確認対象外とする。

固定料金の判定には、プラン変更券の有無、販売対象が全員分そろっているか、現地・オンラインの参加経路がそろっているかを使わない。固定料金と判定した後に、それぞれの不足を別のチェックで検出する。

### 9.3 イベント内のチケット構成

| チケット構成 | 取り得る値 | 判定内容 |
| --- | --- | --- |
| 全回券 | あり／なし | 券名に全N回の表記がある券が存在するか |
| 途中参加券 | あり／なし | 券名に第M回から参加の表記がある券が存在するか |
| 申込み済み券の構成 | なし／一部あり／全券が申込み済み | 申込み済み券が参加申込券のうち何件あるか |

イベント自体の属性もチケット構成も、排他的な1種類へまとめない。同じイベントで、ハイブリッド、固定料金、全N回、全回券あり、途中参加券あり、一部申込み済みが同時に成立できる。

### 9.4 チケットの用途

## 10. 対象外・確認不能・実行失敗の扱い

### 10.1 結果区分

| 結果 | 意味 | 集計・表示 |
| --- | --- | --- |
| 正常 | チェック対象で、取得した値が正しい | OK |
| 不備 | 取得した設定が正しい状態と異なる | NG |
| 確認不能 | 対象だが取得・解析・分類できず結論を出せない | UNKNOWN |
| チェック不要 | そのルールの適用条件に該当しない | 異常件数へ加えない |
| 対象外 | イベント全体が対象外 | チェック対象へ加えない |
| 対象判定不能 | 対象外かどうかを決められない | チェック対象へ加えず別表示 |
| 実行失敗 | 取得、保存、ブラウザ終了などの失敗 | 終了コード1 |
| Slack通知失敗 | Slack本文生成・送信・送達記録の失敗 | 終了コード1 |

取得できた空欄と、画面項目自体を取得できなかった状態を区別する。同じイベントで不備と確認不能が併存してよい。用途を分類できない券は業務不備と断定せず確認不能とし、禁止された用途の組み合わせだけを不備にする。

### 10.2 取得品質

| ID | 確認内容 | 正常条件 | 異常時 |
| --- | --- | --- | --- |
| QUAL-LIST-001 | 一覧の通信 | 正常応答 | 実行失敗 |
| QUAL-LIST-002 | ログイン状態 | ログイン画面へ移動していない | 認証失敗として全体停止 |
| QUAL-LIST-003 | 一覧画面 | 募集中イベント一覧を確認できる | 実行失敗 |
| QUAL-LIST-004 | ページ送り | 次ページが前進し、同じページを循環しない | 全件性不明として実行失敗 |
| QUAL-LIST-005 | 最大ページ数 | 20ページ以内で終了 | 全件性不明として実行失敗 |
| QUAL-LIST-006 | 取得件数 | 重複を除いて1件以上 | 0件を正常終了せず実行失敗 |
| QUAL-DETAIL-001 | 詳細の通信 | 正常応答 | 当該イベントを確認不能 |
| QUAL-DETAIL-002 | ログイン状態 | ログイン画面へ移動していない | 認証失敗として全体停止 |
| QUAL-DETAIL-003 | 詳細画面 | イベント編集画面とタイトルを確認できる | 当該イベントを確認不能 |
| QUAL-DETAIL-004 | イベント設定欄 | 日時、会場、本文を取得できる | 当該イベントを確認不能 |
| QUAL-DETAIL-005 | チケット欄 | チケット欄を取得できる | 当該イベントを確認不能 |
| QUAL-DETAIL-006 | チケット必須項目 | 全券の券名、料金、販売対象、オンライン設定を取得できる | 当該イベントを確認不能 |

詳細1件の一般的な取得失敗は`QUAL-DETAIL-ACQUISITION`として記録し、後続イベントを続ける。ログイン切れは実行全体を停止する。

取得件数は前回成功件数と比較する。初回と前回10件未満は比較しない。前回10件以上で今回が50%未満なら実行失敗とし、前回件数を上書きしない。

### 10.3 集計・表示

- `チェック対象 = OK + NG + UNKNOWN + NG＋UNKNOWN`
- `一覧総数 = チェック対象 + 対象外 + 対象判定不能`
- 対象外をOK・NG・UNKNOWNへ含めない。
- 各ルールを独立して表示し、同じ入力不備が複数ルールの条件に該当する場合もすべて表示する。
- NG・UNKNOWNにはイベント名、開催日時、開催方法、料金方式、料金体系、詳細URL、ルールID、券番号、券名、修正内容または確認不能理由を表示する。
- 券番号はOSIRO画面の1番目からの表示順とする。
- 同じ明細内の券番号・券名は見出しへ1回だけ表示し、修正内容には繰り返さない。券間比較では見出しに券一覧を重ねず、修正内容に不一致となった券番号の組み合わせを表示する。
- イベントは開催日時の降順、日時不明を末尾に表示する。
- 「すべてOK」は、実行完了、取得完全、チェック対象1件以上、全対象が正常、対象判定不能0件の場合だけ表示する。

### 10.4 実行・Slack通知

| 対象 | 正常な処理 | 失敗時 |
| --- | --- | --- |
| 認証・件数保存 | 一時ファイルを確認してから置き換える | 旧状態を保持して実行失敗 |
| ブラウザ終了 | 先行失敗があっても全リソースを閉じる | 終了失敗を実行失敗へ追加 |
| 診断資料 | 秘密情報を除き、管理対象だけ保存・期限削除 | 保存・権限・削除失敗を実行失敗 |
| Slack本文 | すべての不備・確認不能を省略せず生成 | Slack通知失敗 |
| Slack分割 | 1投稿3,900文字以下、イベント境界を優先 | Slack通知失敗 |
| Slack再試行 | 429、5xx、一時通信だけ最大3回 | 最終失敗はSlack通知失敗 |
| Slack途中再開 | 送信済みを除き、未送信本文だけ送信 | 送達不明は自動再送せずSlack通知失敗 |

実行途中で失敗しても、それまでに得た情報から障害通知を作る。Slack自体が利用不能な場合は、コンソールへ理由と試行状況を残す。業務不備・確認不能だけなら終了コード0、実行・取得・通知が失敗した場合は終了コード1とする。

## 11. 料金・販売対象

必須料金区分とは、通常参加券で必ず用意する販売対象（閲覧権限）と回数条件の組み合わせをいう。料金方式が通常料金の場合にSET-001で存在を確認し、通常料金表とゲスト料金表のどちらでも同じ区分を使用する。
