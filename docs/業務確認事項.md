# イベントページ自動チェック 業務確認事項

## 1. この質問票の目的

OSIROでどのイベント設定を正しいとするかを確認するための質問票です。プログラム内部の仕組みを選んでいただくものではありません。

各質問は、実際にあり得るイベント設定と、Slackへ何を修正対象として表示するかで回答できます。選択肢に合わない場合は自由回答へ運用を書いてください。

## 2. 確定済みの業務ルール

資料、現行テスト、これまでの指示が一致しているため、次は再質問しません。

| 業務ルール | 現在の想定 | 根拠 |
| --- | --- | --- |
| 対象外 | 予告、一覧、事務局決済をチェック対象外にする | 外部・内部設計、実装 |
| オフライン判定 | 地域名、東京開催、文学フリマ、猫町.で、旅をしようをオフライン扱い | 過去指示、テスト |
| ハイブリッド | 会場が「オフ会場＋オンライン」なら両方のチェックを行う | 外部・内部設計、テスト |
| 本文の回数表記 | 参加費に1回目があれば「今月1回目」、2回目があれば「今月2回目以降」。両方なければ対象外 | 過去指示、設計、テスト |
| 申込締切 | 締切ONなら開催3日前から開催日まで | 設計、実装、テスト |
| オンラインURL | オンライン開催ONの対象券はURL必須 | 設計、実装、テスト |
| URL一致 | 比較対象のオンラインURLは一致 | 設計、実装、テスト |
| お知らせ締切 | 開始5分前の時刻を記載 | 設計、実装、テスト |
| 受付開始 | 本文に受付開始時刻があれば、お知らせと一致 | 設計、実装、テスト |
| 回数入り券名 | 1回目・2回目以降は「今月」の表記を含める | 設計、テスト |
| 運営メンバー券 | 初心者読書会・ビギナー限定で必要、金額は0円 | 設計、実装、テスト |
| プラン変更券名 | 指定文言へ完全一致 | 設計、実装、テスト |
| プラン変更券の対象 | A、U-22、Bを含める | 設計、実装、テスト |
| 旧会員タグ | プラン変更券以外へA、U-22、Bを入れない | 設計、実装、テスト |
| 全回券 | チケット名に全N回を含む券は通常の単回料金チェックから外す | 設計、実装、テスト |
| 途中参加料金 | 第M回から参加する券は通常の単回料金チェックから外す | 直近仕様、実装、テスト |
| 途中参加券 | オン、オフ、ハイ、外を全体で揃え、オンライン開催をONにする | 直近仕様、実装、テスト |
| 固定費 | 通常料金表との金額チェックは行わない。複数券の金額が互いに違ってもよい | 過去仕様、今回の確認 |
| 駒井さんのイベント | 「ゲスト」が明記されない「駒井さんと読む」は通常料金 | 過去指示、実装、テスト |
| 書名 | チケットに別の括弧付き書名が入っていれば通知。「読書会なし」「読書会セット」は書名扱いしない | 設計、実装、テスト |
| 非会員初参加 | 通常券に加えて初参加券があることを許容 | 設計、実装、テスト |

## 3. Codexが推奨案を決めたシステム運用方針

| 状況 | おすすめする運用 | 理由 |
| --- | --- | --- |
| 一覧や詳細でログイン切れ | その日のチェック全体が完了しなかったとSlackへ通知し、停止する | 残りのイベントを確認できたと保証できないため |
| Slack通知失敗 | Windowsタスクを失敗扱いにする | 担当者へ結果が届いていないため |
| Slackの設定なし | 開始時に停止し、設定不足をエラーとして残す | 通知なしで正常終了する事故を防ぐため |
| ログイン状態の保存失敗 | 実行失敗として通知する | 次回のログイン維持を保証できないため |
| 前回件数の保存失敗 | 実行失敗として通知する | 次回の件数急減チェックを保証できないため |
| OSIROの項目が空欄 | 必須項目なら設定不備としてSlackへ通知する | 実際に未入力であるため |
| OSIRO画面変更で項目を読めない | 設定不備ではなく「システムが確認できなかった」と通知する | 担当者の入力ミスと断定できないため |
| 読めない金額文字 | OSIRO上に不正な文字が保存されていれば設定不備、画面解析の問題なら確認不能として通知する | 原因を誤って担当者へ帰属させないため |
| 本文だけ読めない | 本文項目だけ確認不能とし、チケット等の確認は続ける | 確認可能な不備を隠さないため |
| 不備と確認不能が同時にある | 両方をSlackへ表示する | 確認済みの修正点を隠さないため |
